## Ranked findings

### 1. P1, PROVEN-DEFECT: planned all-match shortcut can retain equality-deleted NaNs

**Location:** `I:crates/iceberg/src/arrow/reader/pipeline.rs:1033`, `:967`; `I:crates/iceberg/src/expr/visitors/strict_metrics_evaluator.rs:303`. Introduced into the planned/equality-delete path by `288a0ee9e`, pinned by Comet `4226d7e3c` and retained by `92bba61b6`.

The new shortcut applies `file_always_matches` to planned filters and equality-delete keep predicates, not just the restricted runtime predicates. Its semantic guard addresses NULLs in `NotEq`/`NotIn`, but does not exclude floating-point comparisons. The strict evaluator treats a NaN-only column as satisfying **every** `NotEq`, regardless of its literal. The actual Arrow kernel can reject an identical NaN.

Concrete counterexample, entirely within the public Iceberg reader API:

1. A data file contains N copies of the same finite-bit-pattern quiet NaN in an optional FLOAT/DOUBLE equality key. Supply legitimate file metrics: `record_count=N`, `value_counts[key]=N`, `nan_value_counts[key]=N`, `null_value_counts[key]=0`. Bounds may be absent.
2. An equality-delete file contains that identical NaN key. The loader deliberately retains floating-point comparison predicates, producing `key IS NULL OR key != NaN` (`I:crates/iceberg/src/arrow/caching_delete_file_loader.rs:670`, `:692`).
3. The strict proof returns true through the `NotEq` arm. The NULL guard passes because the null count is zero. `plan_predicate` sets `row_filter=false`, and the predicate is omitted from Arrow decoding (`I:crates/iceberg/src/arrow/reader/pipeline.rs:612`).
4. `NotEq` row-group evaluation conservatively keeps the group (`I:crates/iceberg/src/expr/visitors/row_group_metrics_evaluator.rs:327`). Page evaluation likewise selects all rows (`I:crates/iceberg/src/expr/visitors/page_index_evaluator.rs:692`). With no position deletes, the deleted NaNs reach the output. An empty output projection counts them too.

Without the shortcut, `PredicateConverter::not_eq` calls Arrow `neq` and rejects identical NaNs (`I:crates/iceberg/src/arrow/reader/predicate_visitor.rs:572`). The locked Arrow source documents total-order comparison and implements it in `/home/unik/.cargo/git/checkouts/arrow-rs-75a881759849662a/fa20c8b/arrow-ord/src/cmp.rs:83`.

There is a related signed-zero consistency failure: file bounds containing only `-0.0`, a planned `key = +0.0`, zero null/NaN counts, and the strict equality proof can remove a filter that Arrow would reject. Iceberg literals use `OrderedFloat` (`I:crates/iceberg/src/spec/values/primitive.rs:32`), while Arrow compares signed zeros distinctly. This example establishes shortcut inconsistency with the existing reader, without asserting that the existing reader's signed-zero semantics match Spark.

**Reachability qualification:** current Comet serialization retains statistics only for INT/BIGINT/DATE/TIMESTAMP/TIMESTAMP_NTZ runtime keys (`C:spark/src/main/scala/org/apache/comet/serde/operator/CometIcebergNativeScan.scala:1243`). It omits float-key statistics, so this is a proven defect in the newly pinned dependency's public reader behavior, **not a demonstrated wrong Spark result through the present serializer**. The existing runtime predicate semantic guard already rejects floating comparison/set predicates (`I:crates/iceberg/src/arrow/reader/runtime_predicate.rs:278`), but that guard does not protect planned/delete predicates.

**Action:** apply an Arrow-semantics proof to planned/equality-delete all-match decisions. Conservatively retain the row filter for floating binary/set predicates until such a proof exists. Add NaN equality-delete and signed-zero tests with real file metrics, including zero-column output.

### 2. P2, PROVEN-DEFECT: scan cancellation leaves delete work detached and can underreport its later reads

**Location:** `I:crates/iceberg/src/arrow/caching_delete_file_loader.rs:209`; `C:native/core/src/execution/operators/iceberg_scan.rs:491`.

`load_deletes` spawns an I/O task and discards its join handle. Dropping its result receiver does not cancel that task, and the task does not check whether the receiver has closed while opening/parsing files. The runtime wrapper has no abort-on-drop behavior (`I:crates/iceberg/src/runtime/mod.rs:37`, `:74`). It retains loader/cache state and can continue requesting storage ranges after the scan stream has been dropped.

Comet drops `inner` and immediately takes a final metrics snapshot. A gated storage reader can hold the detached loader before its next counted read, allow Comet to drop, then release the loader. Subsequent `CountingFileRead::read` increments (`I:crates/iceberg/src/arrow/scan_metrics.rs:44`) have no surviving bridge to the Spark metric. Thus post-cancellation reads can go unreported. This is a real ownership/observability gap; permanent leakage requires nonterminating I/O and is **UNSAFE-ASSUMPTION**, not a proven ordinary-case leak.

The cache fix guarantees that dropping a **load owner** completes waiters. It does not make dropping a **scan receiver** drop that owner. Existing Comet coverage waits for background bytes to advance **before** dropping the scan (`C:native/core/src/execution/operators/iceberg_scan.rs:1084`); it cannot establish that no later I/O or retained state survives cancellation.

**Action:** make detached work ownership explicit. If completion after cancellation is needed for other live cache users, manage shared load lifetimes and metric attribution. Otherwise cancel orphaned work. A dropped scan must not be described as synchronously releasing all delete state without this qualification.

### 3. P2, UNSAFE-ASSUMPTION / UNVERIFIED: shuffle filtering is called redundant without a performance proof

**Location:** `C:native/core/src/execution/operators/dynamic_filter/join.rs:308`, `:326`.

The recognized leaf has already crossed an exchange, so a downstream filter cannot reach the original Iceberg reader. That is a sound reason to say it cannot save source I/O. It does **not** establish that batch filtering cannot save join work. The old consumer evaluates membership and bounds before join probing; bounds can reject keys without full hash probing (`C:native/core/src/execution/operators/dynamic_filter/batch_filter.rs:171`). Removing it feeds every surviving shuffled row to the join. Depending on selectivity, key ranges, batch copying cost, and hash-table behavior, either policy can win.

Also, shuffle decoding is lazy: the scan calls the JVM for subsequent batches and times their decoding (`C:native/core/src/execution/operators/shuffle_scan.rs:130`, `:145`). Recognizing this leaf does not mean every probe batch has already been decoded at planning time. The filter itself cannot prevent that decoding, but the wording that all decode costs are already paid is stronger than the implementation.

No wrong-row counterexample follows from removing this advisory filter. No wall-clock regression is proven. The added test establishes exact inner-join results and absence of a producer, not a performance crossover (`C:native/core/src/execution/operators/dynamic_filter/join/tests.rs:536`).

**Action:** measure selective and nonselective shuffle probes, including wide payloads and tiny/large/duplicate-heavy build sides. Treat this as a cost policy, with a clear no-source-I/O rationale, rather than a semantic redundancy proof.

### 4. P3, PROVEN-DEFECT in observability: the new eligibility rejection is invisible to the skipped counter

**Location:** `C:native/core/src/execution/operators/dynamic_filter/join.rs:77`, `:326`, `:270`; `C:docs/source/user-guide/latest/metrics.md:103`.

The shuffle rejection returns the original join before a wrapper exists. The counter `dynamic_filter_join_filters_skipped` is incremented only inside wrapper execution, so this newly skipped category never increments it. The same condition also prevents batch row-evaluated/pruned/bypassed counters and join-filter publication. It does not suppress ordinary hash-join metrics.

The documentation describes executions with ineligible reader attachment, but the observed counter really describes **eligible wrapper executions that failed reader attachment**. This limitation existed for other rejected join shapes; the new rule adds a prominent category. Narrow the documented scope or expose an eligibility reason/counter at a suitable owner. Do not infer from zero skipped counts that shuffled probes were considered eligible or that the optimization was exercised.

## 1. Exact shuffle condition and join correctness

**SAFE, exact condition:** after the two DataFusion enable flags, `ineligible_reason` inspects the final DataFusion `join.right()` (the probe after build-side selection). It returns true for `ShuffleScanExec`; recursively traverses **any** `ProjectionExec` and **any** `CometFilterExec`; and stops at every other node (`C:native/core/src/execution/operators/dynamic_filter/join.rs:308`). It does not inspect exchange completion, buffered batches, build completion, join type, AQE stage state, broadcast reuse, projection fallibility, filter fallibility, filter projection, or fetch limits. An ordinary DataFusion `FilterExec` is not recognized by this helper.

The unchecked wrappers are safe **for removing a filter**: all their original evaluations remain in place. This helper is not a permission to push filtering across those expressions. `replace_children` reruns eligibility, returning a plain join if a replacement introduces a recognized shuffle probe (`C:native/core/src/execution/operators/dynamic_filter/join.rs:244`).

**SAFE, pruning boundary:** a recognized shuffle leaf cannot also be an Iceberg scan in the attachment traversal. The rule removes all machinery for this join's reader attachment and producer, but cannot remove a direct Iceberg attachment on the same probe shape because none could have been attached there. File pruning upstream of the exchange, Spark dynamic partition pruning, another operator's runtime provider, and TopK/MIN/MAX eligibility are not gated on this helper. They have separate paths. Metadata/statistics planning may still occur upstream without a downstream reader consumer.

**SAFE, completion for actual filtering:** eligible nonshuffle joins permit only `Inner`, `LeftSemi`, and `RightSemi`, ordinary NULL inequality, exactly one direct key, matching supported types, one native partition per input, and resolved `Partitioned`/`CollectLeft` modes (`C:native/core/src/execution/operators/dynamic_filter/join.rs:332`). Partitioned mode is rejected when file partitions are preserved. The locked DataFusion producer finalizes after complete build reports, not per build batch: `/home/unik/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/datafusion-physical-plan-55.1.0/src/joins/hash_join/shared_bounds.rs:555`, `:584`. Its stream first collects the build future at `.../stream.rs:659`. With one native partition, there is no dependency on Spark and DataFusion using identical multi-partition hash routing.

**SAFE, outer/anti joins:** left/right/full outer, left/right anti, and mark joins fail eligibility. NULL-safe join keys fail eligibility. Null-aware anti joins explicitly disable dynamic filtering at the planner (`C:native/core/src/execution/planner.rs:2643`, `:2685`). Source tests cover rejection of these shapes (`C:native/core/src/execution/operators/dynamic_filter/join/tests.rs:474`). Applying ordinary membership pruning to the preserved probe side of an outer/anti join would indeed drop required unmatched rows, but this path does not apply it. Removing a filter by the shuffle rule cannot introduce that row loss.

**UNVERIFIED, Spark orchestration matrix:** AQE can change physical plan shape and broadcast reuse can change how build batches arrive, but neither causes this code to publish a partial build domain. Per-execution state is fresh. Existing AQE/DPP tests do not establish this new optimization under AQE coalescing/skew handling/reuse. The dedicated Spark runtime-join pruning test disables AQE and uses one shuffle partition (`C:spark/src/test/scala/org/apache/comet/CometIcebergNativeSuite.scala:1304`). Distinguish that integration evidence from the source argument about build completion.

## 2. Runtime filter lifecycle, concurrency, NULLs, and types

**SAFE, state ownership:** `DynamicFilterJoinExec` retains an unexecuted template; each execution constructs a fresh `DynamicFilterPhysicalExpr`, reader provider, and reset hash join (`C:native/core/src/execution/operators/dynamic_filter/join.rs:92`, `:134`). EOF/error release the inner stream, and dropping a pending stream drops join/filter ownership (`:186`). Reset detaches a scan provider/order (`C:native/core/src/execution/operators/iceberg_scan.rs:254`). This avoids stale build domains on retry/reexecution. Detached delete loaders are the exception described in finding 2, not evidence of stale join domains.

**SAFE, late arrival/update behavior:** the initial expression is TRUE. Iceberg snapshots at task start, rejects provably impossible files before data/delete I/O (`I:crates/iceberg/src/arrow/reader/pipeline.rs:167`), and uses a live decoder when a provider exists and row-group filtering is enabled (`:194`). A publication during an active row group applies to remaining groups at the next boundary, not already emitted rows or the active group's remaining batches (`I:crates/iceberg/src/arrow/reader/runtime_stream.rs:125`, `:331`). Page selections and position deletes stay scoped to their original row groups. Disabling row-group filtering disables live refresh, but initial task filtering remains. This loses potential pruning, not result correctness.

**SAFE, snapshot/locks within producer contracts:** Comet brackets `current()` with generation reads and makes three attempts (`C:native/core/src/execution/operators/dynamic_filter/iceberg_reader.rs:75`). Locked DataFusion changes expression and generation under its inner write lock. Iceberg uses shared reads for unchanged bound predicates and holds one write lock while snapshotting/binding a changed generation (`I:crates/iceberg/src/arrow/reader/runtime_predicate.rs:200`). No asynchronous storage read is awaited while that cache lock is held. Binding is keyed by generation, task schema, and case policy. Cache failures become None for that generation/context; they are not retried until a relevant change. Snapshot contention can therefore lose pruning for a stable final publication, but it fails open.

**UNSAFE-ASSUMPTION if extended beyond current producers:** Iceberg relies on monotone safe restrictions; it does not prove them. Later None/failures leave an existing task's old restriction in place, and later predicates cannot restore discarded rows (`I:crates/iceberg/src/arrow/reader/runtime_predicate.rs:65`; `runtime_stream.rs:138`). Complete-build joins and tightening TopK/MIN/MAX bounds satisfy this contract. A future partial-build publisher that widens its domain would lose rows. The provider API's generation and monotonicity requirements must remain explicit.

**SAFE, NULL join keys:** ordinary equality never matches NULL, so pruning NULL probe keys after a completed build is valid for supported inner/semi joins. NULLs in the build do not justify any anti/outer filtering. If a literal list contains an untranslatable NULL, translation of that list fails open rather than building an invalid Iceberg literal (`C:native/core/src/execution/operators/dynamic_filter/iceberg_reader/predicate.rs:91`, `:220`). Remaining translated bounds can still be used conservatively. Empty/all-NULL build cases have native decoded-batch coverage; the direct Iceberg join test currently uses non-NULL build keys, so reader-level adoption in these cases remains a test gap.

**SAFE, supported coercion scope:** the wrapper admits identical Arrow key types only: signed integers, DATE32, microsecond timestamps. Computed keys/casts are rejected. The scan mapping further requires one consistent top-level field ID/name and compatible output type across tasks, with case-binding identity checks (`C:native/core/src/execution/operators/iceberg_scan.rs:126`). Timestamp timezone presence selects timestamp versus timestamptz Datum (`C:native/core/src/execution/operators/dynamic_filter/iceberg_reader/predicate.rs:227`).

INT versus BIGINT is not independently coerced by the runtime-filter bridge. Spark must provide a plan with common key types. A widening cast may prevent reader attachment and retain decoded-batch filtering above it. Decimal keys, differing decimal scales, strings/collations, dictionary key types, and floats/NaNs are outside wrapper eligibility. They retain the original exact join. This is conservative exclusion, not an implementation of their pruning semantics. Projected dictionary types and physical schema promotions require reader validation rather than an assumption that logical equality implies physical equality.

**SAFE, evolved physical types:** Iceberg skips runtime row/group pruning on absent or promoted physical fields before adopting a predicate (`I:crates/iceberg/src/arrow/reader/runtime_predicate.rs:308`). File pruning before opening the physical file uses table-level manifest statistics and a type compatibility guard, including checks only for referenced fields (`I:crates/iceberg/src/arrow/reader/pipeline.rs:913`). Runtime floating comparison/set predicates fail open before that statistics path. The separate planned-filter floating shortcut defect remains finding 1.

## 4. Delete cache completion, cancellation, errors, retry

**SAFE, lost wakeups:** equality reservation and its sole completion sender are created atomically under the state write lock (`I:crates/iceberg/src/arrow/delete_filter.rs:153`). Both equality and position waiters create `OwnedNotified` under a state lock, before completion can publish and call `notify_waiters` (`:192`, `:274`). The locked Tokio implementation captures its notify-waiters generation at future construction, so a signal before the first poll is not lost. Completed vectors are merged before the positional guard marks Loaded (`I:crates/iceberg/src/arrow/caching_delete_file_loader.rs:232`).

**SAFE, canceled load owners:** unfinished positional guards publish a retryable failure and notify all waiters (`I:crates/iceberg/src/arrow/delete_filter.rs:106`). Dropped equality senders cause the completion task to publish Failed and notify (`:169`). This replaces the previous equality completion-channel panic. Open/schema/parse errors are sent to equality waiters or published by the positional guard (`I:crates/iceberg/src/arrow/caching_delete_file_loader.rs:304`, `:479`, `:513`). Missing/empty equality IDs produce a shared error before reading. Existing tests include notifications before awaiting, three positional waiters, dropped equality senders, and failure cause/retryability (`I:crates/iceberg/src/arrow/delete_filter.rs:393`, `:409`, `:434`, `:452`, `:487`).

**SAFE, retry policy is sticky per reader:** Failed entries are not evicted. Equality reservations return None for any existing entry; subsequent binding obtains the cached failure. Position reservations return Failed. `cached_load_error` retains source, kind, and retryable metadata (`I:crates/iceberg/src/arrow/delete_filter.rs:219`). Retryable means the caller may retry the operation using a fresh cache/reader, not that this reader retries a failed entry. Comet constructs a new ArrowReader on execution (`C:native/core/src/execution/operators/iceberg_scan.rs:338`), so a new Spark attempt gets a new cache. A same-reader transient-retry guarantee would be false.

**UNSAFE-ASSUMPTION, cancellation and failures outside these guards:** scan cancellation does not abort detached loading (finding 2). The equality completion task itself must remain runnable; it is separately spawned and its handle is ignored. Runtime shutdown or a panic in the outer I/O task can close the task-result channel. `delete_filter_rx.await.unwrap()` remains in the scan pipeline (`I:crates/iceberg/src/arrow/reader/pipeline.rs:520`), so not every possible channel closure is converted into a typed scan error. This is a pre-existing limitation, not newly introduced by the cache fix. In addition, Parquet stream errors are wrapped as Unexpected message strings in `I:crates/iceberg/src/arrow/delete_file_loader.rs:122`, so the shared-error code cannot restore kind/source/retryability already discarded there.

## 5. Architecture and dependency API inventory

**SAFE, boundary direction:** Comet owns Spark/DataFusion planning, per-execution producers, supported expression translation, field identity mapping, and metrics bridging. Iceberg owns task binding, storage I/O, file/group/page/row pruning, physical type validation, and deletes. The provider contains Iceberg predicates and generations rather than DataFusion expressions. Comet uses DataFusion's existing `DynamicFilterPhysicalExpr`, hash-join publisher, and TopK/aggregate publishers instead of introducing a second join-domain engine (`C:native/core/src/execution/operators/dynamic_filter/join.rs:93`, `:140`). The discovery-only consumer does not re-evaluate decoded membership (`C:native/core/src/execution/operators/dynamic_filter/consumer.rs:34`).

**UNVERIFIED, upstreamability/cost:** Iceberg's binding/statistics infrastructure overlaps in purpose with DataFusion `PruningPredicate`, but is not a drop-in duplicate: it uses Iceberg field IDs, manifest metrics, physical schema evolution, and delete selections, and preserves a backend-independent crate boundary. Introducing a DataFusion dependency into that layer would erase this separation. There is still duplicated eligibility/traversal scaffolding for join/TopK/MIN/MAX and two native-reader adapters. The bridge deliberately understands only a few expression shapes and relies on DataFusion's publication shapes. Public shape/semantics tests need to accompany producer changes.

The integration is clean at the predicate boundary but not independently consumable from released dependencies at this pin. ## 6. Regression tests still needed

These are gaps relative to the inspected tests, not claims that no neighboring coverage exists. Every proposed test should compare full result multisets or exact counts against an unfiltered/dependency-baseline path and assert the intended physical plan/reader adoption. Performance cases additionally need work/byte counters and measurements.

1. **P1 dependency test: floating static proof plus deletes.** FLOAT and DOUBLE files containing identical NaNs, full legitimate manifest metrics, equality deletes of the identical NaN. Exercise ordinary/live-capable decoders and projected/empty output; expected count zero. Separately compare opposite signed zeros with planned equality/IN and metrics on/off. Current float runtime fail-open coverage cannot test the planned proof introduced by `288a0ee9e`.
2. **P2 cancellation integration: drop before background completion.** Gate a FileRead at an in-progress equality and positional load, register another task waiting on that file, then drop the Comet scan. Release the gate afterwards. Assert the chosen policy for continued shared loads versus canceled orphaned loads, waiter completion, retained-state release, and bytes requested after drop. 3. **P2 performance policy: shuffled probes.** Same exact inner join with the old batch filter policy and new skip policy; 0.01%, 10%, and 100% selectivity, narrow/wide payloads, small/large/duplicate-heavy builds, raw/projection/filter-wrapped shuffle sources. Include out-of-range keys so min/max prefilter benefits are visible. Do not use byte savings as a proxy for join CPU after an exchange.
4. **Spark runtime-filter AQE/reuse matrix.** Force native broadcast and shuffled hash joins with build-left/build-right, AQE on/off, multiple Spark partitions, coalescing/skew handling where supported, and reused broadcasts.
